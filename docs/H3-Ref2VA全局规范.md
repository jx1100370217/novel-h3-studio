# H3 Ref2VA 全局规范

此规范适用于本仓库所有后续新内容、补镜与重拍，覆盖 MiniMax H3、VDN-H3、FastH3 / FastVideo。输入模式为 Ref2VA 时统一生效，不依赖《考城隍》、项目名或模型选择。其他输入模式继续遵循各自官方格式。

## 编写

新章节的影视化工作单、旧工作流的视觉工作单和分集规划工作单都包含同一份 `AUTHORING_INSTRUCTION`。每镜通过 `ref2va_sections` 提供以下六个字段，顺序不可更改：

1. `subject_definitions`：内容角色、源素材及需要保留的特征。
2. `summary`：实际任务类型前缀和目标视频关系。
3. `retention_analysis`：出现镜头及官方视觉/音频保留标记。
4. `detailed_description`：英文风格开场、按播放顺序的镜头、动作、声音与完整对白。
5. `overall_soundscape`：环境与物理声音。
6. `non_diegetic_music`：默认 `N/A`。

例如 `{subject:actor}` 的身份源写成 `{picture:actor}`，而 `{audio:actor}` 只有真正上传声线参考时才能使用。编译器按实际图片/视频/音频顺序生成 `<Subject N>`、`<Picture N>`、`<Video N>` 和 `<Audio N>`，不要求编剧猜编号。白模视频使用 `{video:spatial_guide}`；静默白模不产生声音参考。

描述正文使用英文；角色对白和歌词在 `<d>[Chinese] 原文</d>` 等语言标签内保留原文，可见场景文字用英文双引号，例如 `A sign reading "营业中" hangs by the door.`。实际发声者从 `(S1)` 开始按首次发声顺序编号，音频定义复用对应角色的编号。

`detailed_description` 在 `[Shot 1]` 前先建立风格。后续镜头用 `[Shot 2] At 00:03.000, ...` 等切点。单镜模型请求保持一个完整动作；切点与对白须落在实际生成时长内。生成任务通常350–500英文词；官方对对白密集或视频编辑任务有例外，不能用机械凑字数或删对白来代替完整表演。

## 执行

公共规则位于 `novel_h3/ref2va.py`。旧版 `director.h3_prompt`、V2 `compile_shot` 都调用它；ComfyUI 的 H3 Ref2VA 节点构建、V2 节点图构建、FastVideo HTTP 请求转换再次校验最终提示词与实际引用。即使编译后的请求被手工改坏，也不能绕过模型边界校验。

校验覆盖六段顺序与非空正文、语言位置、真实素材标签、音频任务与输入匹配、官方保留标记、素材在正文的使用、实际角色/发声编号、完整对白、连续镜号、切点及时长。无BGM请求要求 `non_diegetic_music: N/A`。不合规提示词在入队前报错，不能静默退回旧格式、删对白或换输入模式。

旧编排器的默认结构会补齐官方任务前缀、保留关系和风格开场，然后同样接受公共校验；新内容仍应按工作单完整编写六段，不能把旧模板当作省略动作与声音设计的理由。

历史请求与媒体保持原样，重新提交的新请求执行当前规则。程序校验不能判断画面是否真的出现了动作、声音是否正确或观众是否看懂故事；这些仍须审片。

## 跨镜连续性视频参考

同一场景的续接镜默认使用上一剧情状态镜的静默尾段作为 `<Video N>`，让 H3 从真实的结尾姿态、手与道具位置、服装、光向和屏幕方向继续，而不是只靠文字猜测。插入镜和特写可以回退到最近一个承载剧情状态的镜头；例如手部特写之后接人物反应镜，参考视频应取特写之前的人物状态镜，而不是纸张特写本身。

- 默认截取尾段 2–4 秒，去掉原音频；整段参考容易让模型复制构图和运镜。
- `summary` 使用 `[video continuation + reference generation]`（有对白时再加 `audio reference`）。
- `retention_analysis` 使用 `partially_preserved` 或 `attribute_transfer`，只保留结尾状态、身份、服装、手与道具、光向和屏幕方向；明确写出不复制构图、切点、运镜、旧对白和音频。
- `detailed_description` 必须在 `[Shot 1]` 中自然引用 `<Video N>`，并写清目标镜从该结尾状态如何继续。
- 参考视频不能替代 `open`/`close` 状态文本；两者必须一致，文字仍是审片和校验的主依据。
- 视频参考不保证目标首帧。若 take 仍从更早状态起拍（例如第二次醒来、先躺下再坐起），在第一个符合 `open_state` 的帧裁掉 lead-in，重定时落在裁除区间内的原生台词，并把裁剪记录写进 take 元数据；不要因为后段可用就接受错误开头。
- 项目级开关与路径放在 `authoring.json` 的 `continuity`；逐镜可用 `reference_video` 覆盖为某个镜头 id、显式路径或 `false`。构建器写入 `videos`，`novel_h3.fastvideo_batch` 在提交前刷新尾段并发送 `video_reference`。

## 表演、道具与构图连续性锁

`novel_h3/ref2va_builder.py` 还会根据镜头内容自动注入以下固定锁，项目作者不需要在每镜重复手写：

- **Hand anatomy lock**：出现手、手指、前臂、手腕、掌心时，每只手必须恰好五指一拇指，一个手腕；禁止多余、融合、重复、缺失或分叉手指。A02/A05/A31 这类局部特写必须检查。
- **Costume continuity lock**：每个具名人物保持参考图定义的服装；除非正文明确写出换装，否则相邻镜头不得改变袍色、领口、腰带、帽子或发型。A33/A34 曾出现浅蓝袍与前后深蓝袍不一致，已按此规则修复。
- **Screen-direction lock**：多人或手部插入镜头保持人物在画面的左右侧和手的所有权；从画面右侧入画的手属于画面右侧的人，不得镜像动作。A30/A31 曾出现手从错误一侧入画。
- **Lower-body occlusion lock**：坐在案几/桌后的人物，案几实体遮住下半身；桌下不得出现腿、膝、脚、凳子、坐垫或绿色布料。A18 的关帝桌下腿/凳问题按此锁重渲。
- **Narration-action lock**：旁白描述披衣、进食、上马、饮水等物理动作时，画面必须实际完成该动作并让道具可见；做不到就改旁白或重渲，不能旁白说“披衣”而画面没有披衣。

这些锁是提示词层的硬约束，不是事后修图建议；正式提交前仍须逐镜审片。

## 可见人物与场景参考

每镜的 `cast` 表示该镜实际可见人物，不是整场角色表。编译器在 `[Shot 1]` 中加入总人数及逐身份的身体数量；群体取资产登记的成员数，画外声音身份不占可见人数。自定义 `ref2va_sections` 也执行这一步，最终提交缺失或篡改该段会被拒绝。无名人物（包括只露手臂的信使）逐人写入 `additional_visible_people` 的英文描述列表；未绑定角色的名字不能混入 V2 六段镜头指令，画外听者用明确的画外角色描述。

图片数不等于人数；同一个身份不能用来填满其他考生、官员或空座位。重复资产或相同文件哈希的重复图片输入在提交前拒绝。该检查不识别换编码后的相同像素，也不代替人脸审片。

场景图片必须实际查看：生图指令中的“无人”不保证产物没有神像、肖像或倒影。场景只保留建筑、材质与光线。已确认边缘有人像的场景可在资产条目配置 `generation_crop: {source_sha256, box: [left, top, right, bottom], reason}`；仅对绑定的原图执行 CPU 裁切并保存独立参考文件。源哈希或坐标错误立即报错，不回退到带人像的整图；原图和历史素材保持原样。

`runtime/GENERATION_PAUSED` 存在时，FastVideo、ComfyUI 启动器与生成入口均拒绝加载模型或提交任务。离线编译与已有素材检查仍可执行；只有用户明确恢复后才解除暂停。

持续规则入口：`AGENTS.md` 与 `.cursor/rules/h3-ref2va.mdc`。官方来源为 `h3-prompt-writing/references/ref-en.txt` 及其引用的基础模式指南。
