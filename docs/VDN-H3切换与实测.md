# VDN-H3 切换与实测

2026-09-14，按用户要求将当前小说工作台的默认视频引擎切换为 VDN-H3。角色、场景和分镜图片继续从用户指定的当前 Codex 图片工具交接；模型切换不会改变生图来源。

## 本机配置

- 扩展：[ComfyUI-VDN-H3](https://github.com/Saganaki22/ComfyUI-VDN-H3)，v1.5.2，提交 `3eb63496c24ca70faaf8a14b6c75fcb480e34bf1`。
- 权重：复用本机 `models/vdn/vdn-minimax-h3-int8-convrot-comfyui`，INT8 分支和 Stage-B / Turbo 适配器。文件 SHA-256 记录在项目配置及每条新视频的生成记录中。
- 基础模型：仍用已有 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`。VDN-H3 是在此基础上应用混合注意力、分支及适配器，不是把普通 H3 改个显示名称。
- 采样：`er_sde / beta`，8 步，Turbo 开启，strength 1.0，`merge`，`branch_weights=auto`，`retain_buffers=auto`，`attention_backend=grouped`；没有叠加 SOL 或其他 Turbo LoRA。
- 生成与交付：1920×1088，24 fps；H3 采样尺寸按 32 对齐，成片保留原生画布，不做裁切。VOSR2 仍未启用。
- 续接：Motion Context 仍保留 22 帧视频上下文、24 个音频 latent 上下文，以及同步裁剪和完整 AV latent 保存。

本项目专用 `8191` 服务只加载 Motion Context 和 `ComfyUI-VDN-H3-studio`。VDN 节点指向本项目的固定副本，原有 `8190` 服务及 `custom_nodes/ComfyUI-VDN-H3` 安装保持原样。旧版提交 `b49130c` 的 `record_stream` 行为已被上游后续版本修复，因此当前项目使用独立修正版。

## 兼容配置的实际边界

本机基础模型为 pruned / curve 版本。v1.5.2 的 `merge` 路径会跳过已折叠的 51 项 AdaLN 调制更新；日志确认 Stage-B 合并 104 项、Turbo 合并 208 项，并在 50 个块应用 VDN 分支。这个限制已保留在日志中，**不能将本次结果宣称为完整官方未裁剪权重的逐项等价复现或无损质量保证**。本次复用用户已有的基础权重，没有为了对比另换大模型。

运行日志：`runtime/comfy-vdn.log`、`runtime/comfy-vdn-retry.log`。实际可见 `[vdn] ... applied on 50 blocks`、`[vdn] layout:`、局部 SDPA 后端和 `8/8` 采样完成。完整技术输出与实际视频一同留存。

## 对比方法

对照上一轮实际生成的三个镜头，复用同一机器、基础量化权重、图像、文字分镜、种子、分辨率和交付帧数。旧方案为普通 H3 的 32 步 `res_multistep / simple`；新方案为 VDN-H3 的 8 步 `er_sde / beta`。这是两套实际制作配置的耗时对比，不能仅归因于注意力结构，也不能当作同一步数的算法基准。

续镜分别使用各自方案生成的前一镜 latent，所以续镜输入像素并非相同。对每条任务核对首帧和提示词是否一致，在原始对比数据中记录。所有耗时从 ComfyUI 服务端 `execution_start` 到 `execution_success`，包含本次模型准备、采样、解码与保存；不含队列等待、生图、审片、重拍、合成和超分。旧方案数据来自上一轮历史记录，新方案现场执行；每项各一次，不能代表多次测试分布或稳定的冷启动性能。

## 本机实测结果

RTX 5090 32GB，2026-09-14。每项为一条成功生成任务的服务端实际耗时。

| 镜头 | 视频长度 | 普通 H3 · 32 步 | VDN-H3 · 8 步 | 速度倍数 |
| --- | ---: | ---: | ---: | ---: |
| 洪水首镜 | 5.167 秒 | 193.423 秒 | 69.546 秒 | 2.78 倍 |
| 洪水续镜 | 5.667 秒 | 326.891 秒 | 95.805 秒 | 3.41 倍 |
| 振明狩猎 | 5.167 秒 | 197.151 秒 | 68.160 秒 | 2.89 倍 |
| 合计 | 16.000 秒 | 717.465 秒 | 233.511 秒 | 3.07 倍 |

成功任务累计由 **11 分 57.5 秒降至 3 分 53.5 秒**，用时减少 **67.5%**。按这三个短镜头的工作量折算，每生成 1 分钟视频约需 **14.6 分钟**，原配置约需 **44.8 分钟**；这不是长片总工期预测。

第三条首次尝试在第 4/8 步时随服务进程终止（退出码 143 / SIGTERM）。没有生成完整视频；已保留失败 take `t_cef7f742789d`，重启服务后用同样输入成功重跑。上表不包含这次中断、恢复服务或等待时间，不代表总制作耗时或稳定性统计。未把中断归因于显卡故障或 VDN 算法错误。

可复核数据：[vdn-speed-comparison.json](qa/vdn-speed-comparison.json)，包括六条成功 take 的视频哈希、原始 `comfy_history.json` 路径、起止时间，以及首帧、提示词和种子一致性检查。续镜使用各自引擎的上一条 latent。

## 版本与验证

VDN 设置、扩展提交和权重记录进入镜头指纹。更换引擎后，旧 H3 take 仍保留，但不会被当作新 VDN 视频，也不会把旧引擎的 latent 自动用于新引擎续接。每条新 take 保存 `generation_profile`，工作台显示当前引擎和步数。

原文、资产身份、台词锁定、音频审片和整书覆盖检查继续生效。视频生成成功和模型辅助音频分析不会自动变为成片验收通过。

本机 26 项测试通过，包含 VDN 模型链路、Turbo/8 步一致性、续接裁剪和切换引擎不复用旧 take。真实浏览器验证默认引擎和任务均显示 `VDN-H3 Turbo · 8 步`，截图 `docs/qa/vdn-workbench.png`。
