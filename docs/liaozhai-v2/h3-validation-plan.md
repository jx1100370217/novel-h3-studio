# 《聊斋志异》H3 能力边界与验证计划

状态：2026-10-08，只读审计后的验证设计。**本计划尚未生成样片、运行 benchmark 或证明质量提升。**下文将本地已证实事实与待验证建议分开。

## 1. 已证实的部署与能力

当前项目配置使用 MiniMax H3 Base 的 FL2VA / Ref2VA `pruned_int8_convrot` 权重、Qwen3-VL-32B NVFP4 AWQ 编码器、FP16 视频 VAE 和 FP32 音频 VAE。设置为 20 步 `er_sde/beta`、1376×768、24 fps，交付裁成 1366×768；VDN、FastH3 生产、Blender 引导、超分均关闭。已读取权重头及 S013、S016 保存的实际节点图，不能把当前问题归因于“8 步 VDN”。证据：`projects/liaozhai-zhiyi/config.json:7-53`，`renders/t_6239cc3163b4/prompt.json`，`renders/t_37d3a7a39716/prompt.json`。

本地运行的是 H3 Base，不能等同官方完整托管链路。官方完整系统还包含 Context-IR 输入理解与 Regenerate-2K；这两部分尚未随 Base 开源。Base 联合生成音画，FL2VA 接首尾帧，Ref2VA 接图像、视频及声音参考。普通放大或 VOSR2 应如实标为后期超分。[MiniMax 官方说明](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/README.md)

现有 Ref2VA 把音频送入 `ref_audios`，提示明确只迁移音色；它没有提供音素级强制同步。证据：`novel_h3/comfy.py:881-906`、`novel_h3/director.py:764-765`。本地 `MiniMaxH3AddGuide` 支持音频及时间位置，底层也有音频 noise mask；但官方说明 guide 是每步 conditioning，不能据此承诺精确复述或口型。完整对白 WAV 的 audio anchor / 音频 latent 保持方案是**待验证分支**。[Comfy 原生高级流程](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native#anchoring-guides-at-any-frame-15439)

Blender 开启时确会作为 `ref_videos` 进入模型；当前关闭。它提供视觉参考，不是强制执行空间坐标的约束器。简单对白优先用真人风格构图参考；复杂走位才评估预演价值。

## 2. 先修输入，再评模型

已保存 S013 提示同时要求嘴部表演与闭嘴，而且只传一张首帧，却引用不存在的第二张环境图。S016 提示超过两千个空白分词，重复堆叠角色、空间、声音禁止规则。输入冲突会让采样对照失去意义，应先建立标签解析、模式兼容和声音策略检查。

建议把审计字段、坐标、资产 ID、质检规则留在制作数据中；编译器只输出一致的镜头指令。遵循官方提示结构：FL2VA 三段、Ref2VA 六段，英文描述、中文对白保留在 `<d>` 中；参考标签必须和实际输入一一对应。[官方提示指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)

**对白默认采用 H3 原生联合生成**，先验证短白话台词、音色参考、自然表演及口型。明确有问题的镜头才进入重拍或音频锚定试验；“静默闭嘴画面后贴 TTS”不能作为对白默认补救。自动 ASR、VAD 或运动相关性通过，不代表声音好听、音素口型准确。

## 3. 单 RTX 5090 的分阶段对照

建议先保留现有权重，建立 1344×768、24 fps、20 步 `res_multistep/simple`、shift 12/3 的干净基线，关闭 VDN、Turbo 与额外注意力补丁。这是第一方模板参照，**不是已证明优于当前采样器的结论**。[Comfy 配置说明](https://docs.comfy.org/tutorials/video/minimax/minimax-h3#sampler-and-scheduler)

准备六类生产小样，每类固定两个 seed、每条约 4–6 秒，共 12 条：单人白话对白；双人视线与反应；手递文书；进门行走；暗处神异变化；同人物同场景的相邻镜头。最后一类以一对镜头为样本单元，计费与耗时按实际渲染条数统计。必须使用生产人物和场景，不能用无参考 T2VA 速度代替身份一致性测试。

按顺序验证，禁止展开所有参数的笛卡尔积：

1. 保持旧运行配置，先验证简洁且无矛盾的输入；可复用输入完全匹配的历史结果，否则重建对照。
2. 只在三个代表性难例上比较当前采样器与模板基线；固定资产、台词、时长、seed、运行版本。
3. 对仍有漂移的难例，分别试 20→25 步、`ref_image_size=match→max`，一次只改一个因素；没有收益就停止扩展。
4. 权重精度与编码器对照排在后面。BF16 当前未安装，先评估磁盘、内存、卸载路线及短样可行性；不得宣布“去量化必然更好”。VDN 作为独立加速候选，保留其适配器兼容限制，不与多项改动捆绑。

已有 VDN 报告是三镜各一次的配置耗时对比，续镜条件还不相同；不能作为对白质量或稳定性结论。参见 `docs/VDN-H3切换与实测.md:22-50`。每轮只把胜出配置推广到完整 12 条，再制作 45–60 秒连续剧情验证剪辑与声音衔接，最后重做《考城隍》。

## 4. 评价、成本与停止条件

每条保存模型及资产哈希、prompt、节点图、seed、步数、版本、原始音画、峰值显存/RAM、失败记录。机器查解码、身份风险、ASR、声画时序；人工盲评叙事可读性、表演、声音自然度、视线与物理交互、连续性。记录评分与拒绝原因，不能用“文件生成成功”替代验收。

建议预先登记硬失败：角色换脸或数量错误、关键动作缺失、对白错词漏词、明显错误口型、声轨截断、不可剪接的首尾状态。任何一项出现，该秒数不计入合格产出。一般审美评分采用同一量表并保留两种子的分布；两次结果不足以证明普遍优势，仅能决定是否值得扩大验证。

定义：**每可接受秒成本 = 所有尝试的总成本 ÷ 最终入选且验收通过的去重秒数**。本机分别报告 GPU 运行秒/合格秒、人工审核分钟/合格秒；若核算金额，再加入明确的电费、服务费和人工计价。失败、重拍、启动、解码、后期都进入总账，不能只计成功采样。

先测冷启动与热运行，再用实测中位数及范围估算：总墙钟时间 ≈ 冷启动 + Σ(待拍镜头数 × 单次端到端耗时 × 平均尝试数) + 质检与合成。若人工审核可并行，另列关键路径，避免重复相加。没有实测前不给硬件时间承诺，也不按一次最佳速度外推全书。

关键失败重复出现时，停止批量扩章，回到台词、构图或路由修复。只有连续剧情与整章人工验收通过，才允许按篇章分批扩大生产。
