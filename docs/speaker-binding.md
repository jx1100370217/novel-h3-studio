# 对白、人物和参考音频

正式生成现在有三层检查：

1. 剧本逐句记录 `speaker`，旁白也明确填写“旁白”或“作者旁白”。`speaker_audit` 记录对照原文的理由。修改台词或说话人后，旧审阅不能继续使用。
2. `bible/voices.json` 将角色名称、资产 ID、参考音频及文件校验值关联起来。VDN-H3 提交前检查角色名册、图片位置和音频文件。缺失、未审阅、文件变化、旁白/角色类型不符时拒绝生成。
3. 生成后用本地 Whisper 转写，与目标台词比较。忽略标点和读音完全相同的他/她/它/祂后须逐字一致；出现差异就暂停批次，包括可能的识别错误，留待核对，不容忍可能改变剧情的漏字。原剧本与字幕仍保留原文用字。转写通过不代表声音身份或口型验收。

人物的全局身份由资产 ID 固定；H3 的 `S1`、`Picture 1`、`Audio 1` 是每个生成镜头内部独立编号。编号按实际输入重新解析，不能假定第一张图片就是第一个说话人。

工作台剧本及 H3 分镜保存明确的旁白名称。仅 ArcReel 交换文件按其原生约定将旁白表示为 `kind=voiceover, speaker=null`，明确名称仍在同目录的 H3 文件中，避免破坏 ArcReel 导入校验。

每次提交保存 `renders/<take>/speech_manifest.json`：逐句台词、说话人、图片编号、参考音频路径及哈希。对应的 `prompt.json` 包含真实 `LoadAudio` 节点和 `ref_audios.ref_audio_0` 等连接。音频只迁移音色，参考音频自身的台词不得进入成片。
